# План разработки

Файл содержит только ещё не устранённые проблемы и будущие улучшения. Завершённые пункты следует удалять; текущее поведение документируется в `README.md`.

## P0 — безопасность и корректность учётных данных

### Закрыть SSRF в identity broker

`internal/broker/service.go` использует обычный `http.Client` для настраиваемых token/UserInfo URL. В отличие от back-channel logout, обращения не блокируют loopback, link-local, private и зарезервированные адреса и допускают DNS rebinding.

- Переиспользовать безопасный DialContext из `internal/oidc/outbound.go` или вынести общий клиент в `internal/netx`.
- Отключить proxy и redirects, проверять все DNS-ответы и фактический адрес подключения.
- Если нужны внутренние корпоративные IdP, добавить явный ограниченный allowlist CIDR с fail-closed валидацией.
- Добавить тесты для IPv4/IPv6, DNS rebinding, redirect и proxy.

### Добавить дедлайны и отмену LDAP

`internal/ldap/client.go` принимает `context.Context`, но не использует его: dial, bind и search не имеют конечного deadline и могут зависнуть.

- Выполнять dial с контекстом и конечным тайм-аутом.
- Устанавливать deadline на всё LDAP-соединение и корректно прерывать bind/search при отмене контекста.
- Добавить тесты зависшего сервера, отмены и истечения deadline.

### Устранить известные frontend-уязвимости

`npm audit --omit=dev` обнаруживает три уязвимости высокой серьёзности: XSS в цепочке Vue/`@vue/server-renderer` и DoS в `source-map-js`.

- Обновить lock-файл как минимум до исправленного Vue 3.5.43 и безопасной версии `source-map-js`.
- Проверить совместимость Vite и Vue, собрать production bundle и повторить audit до нулевого результата.
- Добавить `npm audit --omit=dev` в CI.

## P1 — незавершённые сценарии и целостность

### Завершить активацию pending-пользователей

Локальный пользователь со статусом `pending` не может войти, но `POST /api/v1/auth/email/request` доступен только после аутентификации. Создание пользователя администратором не отправляет письмо, поэтому штатного пути активации нет.

- При создании pending-пользователя атомарно выпускать verification token и отправлять письмо либо реализовать безопасный публичный resend без перечисления учётных записей.
- Ограничить частоту повторных писем и аннулировать лишние активные токены.
- Добавить end-to-end тест «создание pending → письмо → verify → вход».

### Сделать федеративное связывание атомарным

При одновременных callback `resolveUser` может создать несколько пользователей. `LinkIdentity` использует `ON CONFLICT DO NOTHING`, не проверяет число строк и позволяет проигравшему запросу создать сессию для не связанной записи.

- Объединить поиск, JIT provisioning и привязку внешнего subject в транзакцию с блокировкой/уникальными ограничениями.
- При конфликте перечитывать победившую связь и не выдавать сессию посторонней записи.
- Для GitHub получать primary verified email через `/user/emails`: scope `user:email` сейчас запрашивается, но не используется; нельзя создавать полноценный профиль с пустым email без явной политики.
- Добавить конкурентный integration-тест двух одинаковых callback.

### Гарантировать аудит чувствительных изменений

Во многих сервисах изменение БД и запись аудита выполняются раздельно. Ошибка аудита после успешной мутации возвращает клиенту 500, хотя изменение уже произошло; для login, MFA, logout и revocation ошибки аудита часто игнорируются.

- Для административных и credential-changing операций сохранять изменение и audit event в одной транзакции либо через надёжный transactional outbox.
- Разделить обязательный security audit и допустимую best-effort телеметрию.
- Добавить тесты ошибок аудита и повторных запросов без двойной мутации.

### Запретить кэширование секретных ответов

Token endpoint и ответы с одноразовыми секретами не устанавливают обязательные `Cache-Control: no-store` и `Pragma: no-cache`.

- Добавить заголовки для OAuth token/introspection, создания и ротации client secret, MFA enrollment/recovery codes и других ответов с credentials.
- Проверить заголовки автоматическими handler/integration-тестами.

### Ограничить память и стоимость локального rate limiter

`TokenBucketLimiter` допускает рост map свыше 10 000 активных ключей и после порога выполняет O(n)-обход при добавлении каждого нового IP. Распределённая атака способна вызвать рост памяти и CPU.

- Ввести жёсткий предел, эффективную LRU/TTL-структуру и метрики вытеснения.
- Добавить нагрузочные тесты множества уникальных IP.
- Реализовать общее состояние для нескольких экземпляров; локальный limiter оставить дополнительным уровнем защиты.
- Документировать fail-open/fail-closed поведение при недоступности общего хранилища.

## P2 — качество, сопровождение и устаревший код

### Расширить автоматические проверки

Пакеты `account`, `rbac`, `users`, `mailer`, `health` и `app` не имеют unit-тестов. Единственный integration-тест не покрывает pending activation, блокировку/разблокировку, broker callback, LDAP timeout, no-store headers и большинство административных CRUD.

- Добавить тесты перечисленных сценариев и up/down-миграций на реальном PostgreSQL.
- Добавить в CI `govulncheck ./...`, `npm audit --omit=dev` и race-тесты в Linux-окружении с CGO.
- Добавить воспроизводимую команду `make quality` или контейнер с закреплёнными версиями инструментов: локально сейчас отсутствуют `govulncheck` и `golangci-lint`, а `go test -race` недоступен без CGO.

### Удалить устаревшие и дублирующиеся реализации

- Удалить неиспользуемый `users.Service.SetPassword` либо подключить его только через безопасную атомарную операцию с отзывом credentials.
- Заменить локальные `clientIP` в users/bootstrap единым helper, читающим нормализованный `RemoteAddr`; текущие копии всё ещё содержат устаревшее чтение `X-Forwarded-For` и безопасны только потому, что глобальный RealIP удаляет заголовок.
- Ограничить принимаемый `X-Request-ID` по длине и формату либо генерировать собственный, чтобы не отражать и не журналировать произвольное значение размером до лимита заголовков.
- Синхронизировать устаревшую версию frontend-пакета `0.7.0` с версией продукта или перейти на единый источник версии сборки.

### Перевести административный интерфейс

Документация и правила проекта требуют русский язык, но практически все подписи, сообщения и placeholders в `web/admin/src` остаются английскими.

- Вынести пользовательские строки в единый слой локализации и добавить русский язык по умолчанию.
- Оставить протокольные идентификаторы и технические значения без перевода.
- Добавить UI smoke-тесты критичных страниц и ошибок.

### Планово обновить frontend-инструменты

После устранения уязвимостей оценить переход с Vite 6 на 8, Pinia 2 на 4, Vue Router 4 на 5 и plugin-vue 5 на 6. Major-обновления выполнять отдельно с проверкой browser support и production bundle.

## Отложенные протоколы интеграции

Реализовывать только после появления подтверждённого потребителя и согласованных требований:

- SAML 2.0.
- SCIM.
- OAuth 2.0 Token Exchange (RFC 8693).

До реализации определить модель угроз, сценарии, совместимые продукты и критерии приёмки.
